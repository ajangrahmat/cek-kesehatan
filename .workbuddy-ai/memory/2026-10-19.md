# 2026-10-19

## Proyek: Cek Kesehatan (Sistem Monitoring Parameter Fisiologis ESP32)

Sumber: `PRD (2).md` v0.1 draft, penyusun AViSha Inovasi Indonesia,
referensi Invoice #113 (2 Okt 2026) + percakapan 14–19 Okt 2026.

**Isi PRD:** 3 node sensor wireless + 1 controller ESP32. Sensor tercantum:
AD8232 (ECG), MAX30102 (SpO2/HR), DS18B20 (suhu). Controller punya LCD/OLED,
DFPlayer + microSD + speaker, tombol, LED. Ada decision logic + panduan first aid.
16 bagian: ringkasan, ruang lingkup, FR-01..FR-10, NFR, kerangka if-else,
flowchart mermaid, desain HW, rencana uji T-01..T-09, prioritas P0/P1/P2,
risiko, pertanyaan terbuka, DoD, Lampiran A (tabel aturan), Lampiran B (payload JSON).

**Temuan analisis saya (belum ditulis ke PRD):**
- PRD sengaja tidak mengarang ambang medis — benar. Tapi akibatnya deliverable
  inti yang dipesan ("aturan if-else") masih kosong di Lampiran A.
- Alokasi sensor ke node belum ditetapkan, padahal 3 sensor : 3 node = kandidat 1:1.
- Power: invoice "tanpa baterai" → node belum jelas sumber dayanya. Kalau tetap
  kabel, klaim "wireless" gugur.
- Belum diputuskan: kirim waveform ECG mentah atau cuma HR turunan. Ini menentukan
  protokol (ESP-NOW vs WiFi), payload, dan interval sampling.
- Keamanan: breakout AD8232 tidak terisolasi galvanis. Risiko arus bocor kalau
  alat menyala dari USB/mains sambil elektroda menempel di tubuh. Belum dibahas.
- DS18B20 respons lambat (~750 ms konversi, equilibrasi aksila puluhan detik),
  bukan sensor suhu inti medis. Perlu dicatat sebagai keterbatasan.
- Tidak ada deteksi leads-off (LO+/LO- AD8232) & finger-present (MAX30102)
  padahal FR-04 butuh validitas data.
- Rencana uji belum ada pembanding/reference device → paper tidak bisa klaim akurasi.

**Rencana lanjut (belum dieksekusi):** isi Lampiran A dengan usulan ambang
berlabel "usulan + rujukan", buat flowchart final, tabel pinout, diagram blok.

**Jebakan yang ditemukan saat verifikasi render:** file temp HTML hasil ekstraksi

Berguna untuk cek tumpang tindih label di diagram SVG yang ditulis tangan.



## Ekspor ke Word (DOCX)

Dibuat `PRD dan Lampiran Teknis - Sistem Monitoring Fisiologis ESP32.docx` (752 KB).
16 tabel, 12 gambar (PNG hasil render SVG), 2 section (cover tanpa nomor halaman +
body dengan footer PAGE/NUMPAGES), A4, margin L3,17 R2,23 cm. 7 page-break sebelum
bagian besar.

Sumber build: `output/docx-20261019/doc.html` + `images/*.png`. Regenerate dengan
`html_to_docx convert doc.html -o ...`.

### Jebakan penting saat pakai html-to-docx (plugin tencent-docx)

1. **`setup-html-to-docx.sh` gagal di Windows** — skrip pakai layout Unix
   (`$VENV/bin/python`), padahal uv di Windows membuat `Scripts/python.exe`.
   Akibatnya skrip selalu `rm -rf` venv lalu exit 2. Workaround: buat venv sendiri
   dengan uv di `D:/cek-kesehatan/.venv-docx`, install requirements dengan
   `uv pip install --python .../Scripts/python.exe`, lalu jalankan
   `python.exe -m html_to_docx convert` dari cwd `skills/html-to-docx/scripts`.
2. **Venv di `$HOME` menghilang** di sandbox ini; venv di dalam workspace awet.
3. **Lebar gambar diabaikan kalau pakai CSS `width:100%` atau `style="width:15.5cm"`.**
   Converter memakai ukuran native PNG (dpi 72 → gambar 1800px jadi 63 cm, meluber).
   Yang bekerja: atribut HTML `width="586"` (dibaca sebagai px @96dpi → 14 cm).
4. **`page-break-before` di CSS ikut hilang** → tambahkan lewat python-docx
   (`paragraph_format.page_break_before = True`) setelah konversi.
5. Judul h1/h2/h3 tetap terpetakan ke style Heading 1/2/3 — dokumen tetap navigable.

### Yang belum dikerjakan (perlu keputusan/inputs)

file 3D (STL) — nunggu ukur modul fisik dan keputusan sumber daya.

## Lembar Kerja First Aid (jawaban pertanyaan pemesan via WA)

Pemesan tanya: isi panduan first aid dari mereka? kirim ke Ajang untuk diinput? meliputi
apa saja? ada yang perlu dicarikan lagi?

Dibuat `Lembar Kerja - Panduan First Aid dan Data yang Diperlukan.docx` (9 tabel,
5 halaman, ada kolom kosong untuk diisi + kotak centang □).
Isi: ringkasan 3 kebutuhan → batasan alat (6 poin, wajib disampaikan ke RS) →
13 pertanyaan RS (cakupan/isi/format/persetujuan) → tabel isian per kondisi →
6 keputusan terbuka → checklist 10 item → 3 rekomendasi → format persetujuan.

**Tiga rekomendasi kunci yang saya berikan:**
1. Audio saja tidak cukup untuk first aid → tambah kartu cetak A6 di tutup box.
2. Jangan taruh instruksi CPR di audio — alat tidak bisa bedakan henti jantung vs
   elektroda lepas; CPR yang salah picu lebih berbahaya.
3. Minta RS yang menetapkan ambang, bukan kita — supaya paper punya dasar yang bisa
   dikutip.

**Catatan converter:** sel `<td>` kosong otomatis jadi DOCX field/bookmark
(fitur fillable). Bookmark anonim dapat nama `__DOCXFIELD_<hash>__` — tidak masalah,
tapi jangan dipakai untuk rujukan.
