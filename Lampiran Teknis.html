Sistem Monitoring Parameter Fisiologis Berbasis ESP32

Tanggal 19 Oktober 2026 Penyusun AViSha Inovasi Indonesia Status Usulan — butuh persetujuan Melengkapi PRD v0.1
Batas dokumen. Semua angka di sini adalah usulan yang disertai rujukan umum — bukan protokol klinis, bukan hasil pengujian, dan bukan alat diagnosis. Ambang berlaku untuk dewasa saat istirahat, tidak untuk anak, bayi, atau ibu hamil.

1Cara Kerja Sistem

Sistem terdiri dari 4 unit alat: tiga node sensor dan satu controller. Enam langkah berikut berulang selama alat menyala:

  1. Node membaca sensor. Tiap node punya satu sensor, membaca 1× per detik, lalu memvalidasi secara lokal: elektroda menempel atau lepas, jari ada atau tidak, CRC suhu benar, nilai masuk rentang teknis.
  2. Node mengirim paket. Berisi identitas node, nomor urut, waktu, nilai sensor, dan satu flag validitas — lewat ESP-NOW, 1× per detik.
  3. Controller memeriksa kesegaran data. Tidak ada paket selama 3 detik berarti node ditandai TERPUTUS, dan nilai terakhirnya tidak dipakai sebagai data terkini.
  4. Controller mengklasifikasi. Hanya data dengan flag valid = 1 yang diklasifikasi, lalu digabung menjadi satu status sistem.
  5. Controller menampilkan dan berbunyi. Status ke OLED; bila memicu audio, DFPlayer memutar track yang sesuai.
  6. Controller mencatat. Setiap perubahan status dicatat sebagai bahan paper.

Prioritas status sistem

TERPUTUS > TIDAK VALID > GAWAT > PERHATIAN > NORMAL

Kehilangan data tidak boleh menutupi kondisi bahaya, dan kondisi bahaya tidak boleh menyamarkan bahwa ada node yang mati.

2.1 Daftar alat — 4 unit

Konsekuensi yang perlu dihitung sejak awal:

  • Firmware tetap dua build, bukan empat. Satu firmware node di-flash tiga kali dengan NODE_ID berbeda (1, 2, 3), plus satu firmware controller.
  • Empat catu daya terpisah harus siap sebelum uji integrasi. Invoice hanya menyebut unit charging/power tanpa baterai — keempat alat belum bisa dinyalakan bersamaan sampai sumber dayanya diputuskan.
  • Controller harus mengenali tiga MAC node. Usulan: tabel MAC di firmware, dengan tombol pairing untuk mendaftarkan node baru tanpa kompilasi ulang.
  • Empat box, bukan dua. 3 box node + 1 box utama. Kalau ketiga node memakai desain yang sama, cukup satu file 3D yang dicetak tiga kali — ini juga alasan pertanyaan nomor 7 di bagian 10.

Pemetaan 1:1 paling wajar dari invoice (3 sensor, 3 node). Kalau node ketiga ingin dijadikan cadangan, cukup dikosongkan — firmware controller tidak berubah.

2.3 Yang dikirim: nilai turunan, bukan waveform ECG

Usulan: kirim HR, SpO2, suhu, dan status validitas — bukan waveform ECG mentah.

  • OLED 128×64 tidak mungkin menampilkan trace ECG yang berguna.
  • Waveform 250 Hz × 3 node tidak muat nyaman di satu kanal ESP-NOW.
  • Untuk paper, angka + tren + tabel status sudah cukup kuat; waveform menambah klaim yang tidak bisa dipertanggungjawabkan tanpa validasi.

Bila tetap diperlukan, waveform dikirim sebagai burst 500 sampel hanya saat tombol ditekan (P2), bukan streaming terus-menerus.

Soal ECG. Sistem ini tidak menginterpretasi irama jantung. Satu lead tidak cukup untuk itu, dan klaim aritmia tidak boleh muncul di paper. Yang dilaporkan hanya: elektroda terpasang/lepas, HR turunan, dan konsistensi HR terhadap PPG.

3.3 Histeresis dan debounce

Ambang angka saja tidak cukup — nilai yang berayun di batas akan membuat status berkedip dan audio berbunyi berulang.

  • Perubahan status hanya berlaku bila kondisi bertahan ≥ 3 detik berturut-turut.
  • Keluar dari GAWAT butuh melewati ambang sebesar margin 2 satuan (mis. HR harus turun di bawah 118 sebelum TAKIKARDIA BERAT dilepas).
  • Nilai yang hilang tidak dihitung sebagai normal — dibekukan dan diberi tanda --.

Aturan pemutaran

  1. Hanya satu track diputar pada satu waktu.
  2. Audio gawat (prioritas 4) tidak boleh dipotong oleh prioritas lebih rendah.
  3. Kondisi yang sama tidak diulang sebelum 30 detik berlalu.
  4. Maksimal 3 kali pengulangan per kondisi; setelah itu senyap sampai kondisi berubah.
  5. Kembali ke NORMAL tidak memicu audio kecuali sebelumnya ada kondisi gawat.

8Format Data

Struct biner untuk ESP-NOW (± 40 byte):

// dikirim lewat ESP-NOW, bukan JSON
typedef struct __attribute__((packed)) {
    uint8_t  node_id;    // 1..3
    uint16_t seq;        // naik terus, deteksi paket hilang
    uint32_t t_ms;       // millis() node saat baca
    uint8_t  q;          // 1 = valid, 0 = tidak valid
    uint8_t  err;        // 0=ok, 1=elektroda, 2=PPG, 3=suhu, 9=umum
    int16_t  hr;         // bpm, -1 = tidak ada
    uint8_t  spo2;       // %, 0 = tidak ada
    int16_t  temp_x10;   // °C x10, -1 = tidak ada
    uint16_t vbat_mv;    // tegangan suplai
} NodePacket;

Versi JSON hanya untuk log dan paper:

{"n":1,"seq":1234,"t":56789,"q":1,"err":0,"hr":78,"spo2":0,"temp":0,"vbat":4020}

10Yang Masih Harus Dikonfirmasi

Tujuh hal, urut dari yang paling menghambat:

  1. Alokasi sensor per node — setujui usulan 1:1?
  2. Sumber daya 4 alat — invoice menyebut tanpa baterai. Tiap unit disuplai kabel, power bank, atau baterai terpisah? Ini menentukan klaim "wireless" dan apakah keempat alat bisa menyala bersamaan saat uji integrasi.
  3. Ambang di bagian 3.2 — disetujui, atau ada angka dari pembimbing?
  4. Subjek uji — dewasa sehat, atau ada skenario pasien? Mempengaruhi etika dan klaim.
  5. Bahasa dan isi audio — draf bagian 6 disetujui?
  6. Isi panduan first aid — siapa yang menyusun dan menyetujui? Ditampilkan di OLED atau dokumen terpisah?
  7. Tiga node identik atau berbeda? Satu desain PCB yang sama untuk ketiga node (hanya sensor yang diganti) jauh lebih murah dan lebih cepat dirakit daripada tiga PCB berbeda. Ini mempengaruhi desain casing juga.
